FP in Scala · Lesson 4

Pattern matching on outcomes

From a modelled choice to a spoken result — and the compiler has your back. ~20 minutes.

Last lesson you modelled a choice: an AttackResult is a Hit, a Miss, or a Critical — a sum type. But so far all you can do with one is print it. Today you'll take it apart: look at which case a value is, pull out its data, and turn it into a line of combat narration. The tool is match, and it pays back the promise Lesson 3 made — the compiler will check you've handled every case.

The tool: match

You give match a value and a list of cases. It finds the first case that fits and produces that case's result: 

def narrate(result: AttackResult): String =
  result match
    case AttackResult.Hit(dmg)      => s"A solid hit for $dmg damage."
    case AttackResult.Critical(dmg) => s"CRITICAL — $dmg damage!"
    case AttackResult.Miss          => "A clean miss."

Two things are happening at once. First, each case tests which alternative the value is. Second — and this is the part you couldn't do before — Hit(dmg) binds the payload: the name dmg is a fresh val holding the number inside that Hit, ready to use on the right of the =>. That's how you finally read the data a case carries. [Scala 3 Book: match]

The big idea: match is an expression

A C# switch statement just runs branches — it does something. A Scala match returns a value: the whole result match … evaluates to the string, which is why we can hand it straight back as the function's result. (C#'s newer switch expression works the same way — if you've used it, you already have the mental model.) "Everything returns a value" is a drumbeat you'll hear all through FP.

The payoff: exhaustiveness

Because an enum has a fixed, finite list of cases, the compiler knows the complete set. If your match forgets one, it tells you — before the program ever runs. This is the safety net Lesson 3 promised, and you're about to trip it on purpose.

Do it

1

Add narrate and use it

Open your attacks.scala from last lesson. Keep the enum, and replace the body of combat() so the file reads:

enum AttackResult:
  case Hit(damage: Int)
  case Critical(damage: Int)
  case Miss

def narrate(result: AttackResult): String =
  result match
    case AttackResult.Hit(dmg)      => s"A solid hit for $dmg damage."
    case AttackResult.Critical(dmg) => s"CRITICAL — $dmg damage!"
    case AttackResult.Miss          => "A clean miss."

@main def combat() =
  val log = List(
    AttackResult.Hit(6),
    AttackResult.Miss,
    AttackResult.Critical(12),
    AttackResult.Hit(3)
  )
  log.foreach(r => println(narrate(r)))

foreach runs the little function r => println(narrate(r)) once per element — the same x => … lambda shape you saw with find in the reference.

2

Run it

scala-cli run attacks.scala

Each outcome comes out as a sentence — the match turned data into words:

A solid hit for 6 damage.
A clean miss.
CRITICAL — 12 damage!
A solid hit for 3 damage.
3

Break it on purpose (the win)

Now delete the Miss line from narrate — leave only Hit and Critical — and run again. The program still tries to compile, but Scala stops you with a warning like: 

[warn] match may not be exhaustive.
[warn] It would fail on pattern case: AttackResult.Miss

Read that as: "you claim to handle every outcome, but a Miss could slip through." The compiler enumerated your enum, compared it against your cases, and found the gap — at compile time, before a single attack was rolled. (If a Miss did reach that match at runtime, you'd get a MatchError — but you were warned long before.)

Milestone

Put the Miss case back. You've now closed the loop: model a choice as a sum type, and the compiler guarantees you consider every case whenever you act on it. That guarantee is exactly what makes the next step — a pure function that resolves an attack — safe to build.

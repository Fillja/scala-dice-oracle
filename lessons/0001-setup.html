FP in Scala · Lesson 1

Setup & your first Scala run

One tool. One file. Then IntelliJ. ~30 minutes.

Our whole toolchain is deliberately tiny: one command-line tool (Scala CLI) and one editor (IntelliJ IDEA). That's it — no separate JDK to install, no build tool, no frameworks. This keeps the inner workings visible, which is exactly what our mission asks for.

Why Scala CLI

Since Scala 3.5.0, Scala CLI is the official scala runner. It downloads and manages the Java runtime and the Scala compiler for you the first time you run something — so "install Java" and "install Scala" collapse into a single step. [docs: under the hood]

Part A — Command line first (the fast win)

1

Install Scala CLI

Open PowerShell and run:

winget install virtuslab.scalacli

Close and reopen PowerShell afterwards so the new scala-cli command is on your PATH. Then confirm it's there: 

scala-cli version

You should see a version number print. If you do, the tool is installed.

If winget isn't available

Download the MSI installer from the Scala CLI releases page instead. On a bare Windows machine you may also need the Visual C++ redistributable. Tell me if scala-cli version errors and we'll debug it together.

2

Write a hello-world file

Create a file called hello.scala in your project folder (F:\Programmering\Projects\learn-scala) with exactly this: 

@main def hello() =
  val who = "dice roller"
  println(s"Hello, ${who}! Scala is running.")

A few things to notice — we'll unpack all of these in later lessons:

  • @main marks the program's entry point (like static void Main in C#).
  • val is an immutable binding — once set, who can't be reassigned. This is the FP default, and it's the first habit we'll build.
  • Indentation defines the block — Scala 3 needs no curly braces here.
  • s"...${who}..." is an interpolated string, like C#'s $"...{who}...".
3

Run it

From the same folder, in PowerShell:

scala-cli run hello.scala

The first run will be slow — and that's the interesting part. Watch the output: Scala CLI is downloading a Java runtime and the Scala compiler, then compiling your file. Later runs reuse them and are fast. When it finishes you should see: 

Hello, dice roller! Scala is running.
Milestone

You just compiled and ran Scala from nothing but one installed tool. This is the whole toolchain — everything else we build sits on top of this.

Part B — Bring in IntelliJ

The command line proves the toolchain works; IntelliJ gives you autocomplete, red squiggles, and one-click running while you learn.

4

Install IntelliJ IDEA + the Scala plugin

  • Install IntelliJ IDEA Community Edition (free) from jetbrains.com/idea/download — the Community build is enough for everything we'll do.
  • On first launch, go to Settings → Plugins → Marketplace, search Scala, install the JetBrains Scala plugin, and restart when prompted.
5

Open the project via BSP

In PowerShell, from your project folder, generate the IDE config once: 

scala-cli setup-ide .

Then in IntelliJ: File → Open, select the learn-scala folder, and if asked how to import it choose BSP. IntelliJ will use Scala CLI itself to compile and run — the IDE and the command line stay perfectly in sync. [JetBrains: Scala CLI in IntelliJ]

If it asks for a Project SDK

Pick Download JDK in the SDK dropdown and choose a recent LTS (e.g. 21). Let IntelliJ fetch it — still no manual JDK juggling.

6

Run hello-world from inside IntelliJ

Open hello.scala. A green ▶ Run arrow appears in the gutter next to @main def hello(). Click it. The same greeting should print in IntelliJ's Run panel.

Milestone

You now have a working, minimal Scala 3 environment and can run code two ways: terminal and IDE. Setup is done — from here on it's all functional programming.
